# Деплой фикса: ФИО ученика передавалось ИИ в промпте заметки для учителя

**Коммит:** смотреть `origin/master`, коммит с сообщением `fix: stop sending student full name to AI in teacher summary prompt`
**Файл:** `backend/src/services/report-generator.ts`

## Что чинит

При генерации итогового отчёта (`generateReport`) для поля `ai_summary_for_teacher`
(заметка для учителя) в промпт к ИИ подставлялось `session.student_name` —
реальное ФИО ученика (`s.full_name` из таблицы `students`). Из-за этого ИИ
"знал" имя ученика и мог упоминать его в сгенерированном тексте комментария,
хотя персональные данные учеников не должны передаваться в ИИ-сервис.

Промпт для ученика (`ai_summary_for_student`) и промпты поштучной проверки
заданий (`ai-checker.ts`) ФИО никогда не содержали — затронут только один
промпт в `report-generator.ts`.

## Шаги на проде

1. Забрать коммит (без force, обычный fast-forward):
   ```bash
   cd /path/to/autocheck   # рабочая копия на проде
   git fetch origin
   git log --oneline HEAD..origin/master   # ожидается: коммит fix про PII/student_name
   git merge --ff-only origin/master
   ```
   Если на проде есть незакоммиченные/неспушенные изменения — сначала
   разобраться с ними (`git status`), не затирать.

2. Пересобрать backend (меняется только `.ts`):
   ```bash
   cd backend
   npm run build
   ```

3. Перезапустить backend-процессы, которые генерируют отчёты (worker и api,
   т.к. `generateReport` может вызываться из обоих):
   ```bash
   pm2 reload autocheck-api
   pm2 reload autocheck-worker
   pm2 logs autocheck-worker --lines 50   # убедиться, что стартовало без ошибок
   ```

4. Проверить — сделать тестовую проверку/перепроверку любой работы и
   убедиться, что заметка для учителя в отчёте не содержит ФИО ученика
   (или, если случайно совпадёт по смыслу текста, что промпт в коде
   действительно больше не передаёт `session.student_name`).

## Важно — старые отчёты не пересчитываются автоматически

Фикс влияет только на НОВЫЕ генерации отчётов. Уже сохранённые в БД
`ai_summary_for_teacher` для отчётов, сгенерированных ДО деплоя, могут
содержать ФИО ученика в тексте — они не переписываются автоматически.
Если нужно вычистить историю, отчёт нужно перегенерировать вручную
(кнопка «Проверить заново» в интерфейсе или повторный вызов
`POST /api/checks`), либо, если критично, обновить `ai_summary_for_teacher`
в БД точечно/массово отдельным скриптом — это отдельное решение, требует
токенов ИИ на каждую переоценку.

## Проверка на утечки в других местах (сделано в рамках этого фикса)

Проверены все точки вызова ИИ в проекте:
- `ai-checker.ts` (`checkWithAI`, `callBatchAI`) — ФИО не передаётся, только
  текст задания/критерии/ответ ученика/класс/предмет/тема.
- `report-generator.ts` — единственное место утечки, исправлено.
- `api/platform.ts` — промпт мониторинга платформы, ФИО учеников там в
  принципе нет (только метрики производительности).

Ручной аудит остальных промптов при следующих изменениях всё равно
рекомендуется — новый код может случайно снова начать передавать `full_name`,
`login` или другие персональные поля в промпт.
