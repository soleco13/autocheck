# Деплой: учебники — общий ресурс + надёжные обложки + фикс вёрстки

**Коммит:** смотри `git log -1` на момент чтения этого файла (один общий коммит
за сессию — сообщение начинается с `fix:`), репозиторий `soleco13/autocheck`.

## Что чинит (3 связанных фикса в одном коммите)

### 1. Учебники стали общим ресурсом для всех учителей
Раньше `rag_documents` фильтровался по `teacher_id` — каждый учитель видел,
использовал (в RAG-проверке) и мог удалять/переиндексировать только СВОИ
загруженные учебники. Учебник, загруженный одним учителем, был бесполезен
для проверок другого учителя по тому же предмету/классу.

Убрана фильтрация по `teacher_id` в:
- `backend/src/api/textbooks.ts` — `GET /`, `GET /:id/cover`, `GET /:id/status`,
  `POST /:id/reindex`, `DELETE /:id` (upload по-прежнему пишет `teacher_id`
  как "кто загрузил", просто это больше ничего не ограничивает).
- `backend/src/services/rag-retriever.ts` — `retrieveChunks`, `checkRagStatus`,
  `checkRagAvailability` — теперь ищут учебник по `subject_code`/`grade` СРЕДИ
  ВСЕХ загруженных учебников, а не только у текущего учителя.

Решение сознательное — **полный общий доступ**, включая удаление/переиндексацию
чужих учебников (подтверждено явно, не догадка). Если на проде это не то, что
нужно — обсудить с человеком, не откатывать молча.

Миграция БД не требуется — это чисто прикладная логика (WHERE-условия), схема
не менялась.

### 2. Обложки учебников: рендер на сервере вместо браузера
Раньше: `rag-indexer.ts` через `pdf-lib` вырезал 1-ю страницу оригинального PDF
в мини-PDF (`covers/{id}.pdf`), а браузер (`PdfCover.tsx`) сам рендерил её через
`pdfjs-dist` на canvas при каждом открытии страницы. Это было причиной обеих
жалоб: обложка появлялась "через раз" (гонки/сбои клиентского рендера, worker
на каждую карточку) и страница долго грузилась (N учебников = N независимых
PDF.js воркеров и декодирований при каждом заходе на страницу).

Теперь: `backend/src/services/cover-renderer.ts` рендерит 1-ю страницу PDF в
PNG ОДИН РАЗ при индексации (через `pdfjs-dist` + `@napi-rs/canvas`,
серверный canvas без Cairo/системных зависимостей — нативный prebuilt-биндинг),
сохраняет `covers/{id}.png`. `GET /:id/cover` отдаёт готовый PNG напрямую.
Фронтенд (`PdfCover.tsx`) — теперь просто `<img src=".../cover">`, никакого
`pdfjs-dist` в браузере больше нет.

**Важно про версию `pdfjs-dist` на бэкенде:** намеренно закреплена
`^3.11.174` — это последняя версия с CJS-сборкой (`legacy/build/pdf.js`).
Начиная с v4 пакет стал ESM-only (`build/pdf.mjs` без CJS), что несовместимо
с текущим бэкендом (`"module": "commonjs"` в tsconfig, без плана перехода на
ESM). **Не обновлять `pdfjs-dist` на бэкенде до мажорной версии без отдельного
переезда на ESM** — `npm update`/`npm audit fix --force` могут попытаться
это сделать автоматически, проверить `package.json` после.

### 3. Вёрстка страницы "Учебники": длинный заголовок ломал сетку
`.card` (карточка учебника) — прямой grid-item в `.grid-3`
(`grid-template-columns: repeat(3, 1fr)`). У grid/flex-итемов браузер по
умолчанию `min-width: auto`, а заголовок в карточке — `white-space: nowrap`,
поэтому длинное название без пробельных точек переноса растягивало всю
grid-колонку вместо того, чтобы обрезаться по `text-overflow: ellipsis`
(который на самом div уже был, но не срабатывал). Фикс — один CSS-файл,
`frontend/src/index.css`: добавлен `min-width: 0` в базовый класс `.card`.
Общий класс, безопасно для всех страниц (эффект есть только у grid/flex-детей).

## Новые зависимости — ОБЯЗАТЕЛЬНО `npm install`, простого `git pull` мало

**backend/package.json:**
- `+ @napi-rs/canvas` — нативный (prebuilt-биндинг) canvas для Node,
  используется для рендера PNG-обложек.
- `+ pdfjs-dist@^3.11.174` — см. предупреждение о версии выше.
- `- pdf-lib` — больше не нужен, обложки теперь не вырезаются в мини-PDF.

**frontend/package.json:**
- `- pdfjs-dist` — полностью убран (был только в `PdfCover.tsx`).
- `vite.config.ts` — убрана `optimizeDeps.include: ['pdfjs-dist']`.

## Шаги на проде

1. Забрать коммит:
   ```bash
   cd /path/to/autocheck
   git status   # убедиться что нет незакоммиченных изменений
   git fetch origin
   git log --oneline HEAD..origin/master
   git merge --ff-only origin/master
   ```

2. Поставить зависимости в обоих пакетах:
   ```bash
   cd backend && npm install
   cd ../frontend && npm install
   ```

3. **Проверить, что `@napi-rs/canvas` реально загружается на этой платформе**
   (у него prebuilt-биндинги под основные ОС/архитектуры, но лучше убедиться
   явно, особенно если прод — контейнер/Alpine с musl):
   ```bash
   cd backend
   node -e "console.log(require('@napi-rs/canvas').createCanvas(10,10).encodeSync('png').length)"
   ```
   Должно вывести число (размер PNG в байтах), без ошибок. Если падает —
   писать сюда стоп, разбираться с платформой ДО того как рендер обложек
   начнёт молча падать в проде (он не критичен и просто логирует warning,
   значит без этой проверки заметить проблему сложно).

4. **Смигрировать существующие обложки** со старого формата (`covers/{id}.pdf`)
   на новый (`covers/{id}.png`). Обязательно — иначе `GET /:id/cover` для уже
   загруженных ДО этого деплоя учебников будет 404 (роут теперь ищет `.png`),
   и в интерфейсе для них покажется заглушка-иконка книги вместо обложки, пока
   кто-то вручную не нажмёт "Переиндексировать". Оригиналы PDF уже удалены
   после индексации — единственный источник для регенерации это существующий
   `.pdf`-файл обложки, скрипт рендерит из него:
   ```bash
   cd backend
   node scripts/migrate-covers-to-png.js
   ```
   Скрипт идемпотентный (пропускает id, для которых `.png` уже есть) — можно
   спокойно перезапускать. Выведет сводку: сколько сконвертировано/пропущено/
   упало с ошибкой.

5. Пересобрать фронтенд (зависимость убрана, конфиг vite поменялся):
   ```bash
   cd frontend
   npm run build
   ```
   Backend пересборка не нужна — процессы в `ecosystem.config.js` запускаются
   через `ts-node-dev` прямо из `src/`, не из `dist/`.

6. Перезапустить процессы (реально названия из `ecosystem.config.js`:
   `autocheck-backend`, `autocheck-worker`, `autocheck-frontend`):
   ```bash
   pm2 reload autocheck-backend
   pm2 reload autocheck-worker
   pm2 reload autocheck-frontend
   pm2 logs autocheck-backend --lines 50   # без ошибок при старте
   ```

7. Проверить, что фикс применился:
   - Зайти на `/textbooks` под ДВУМЯ разными учительскими аккаунтами — списки
     учебников должны быть идентичны (общий ресурс).
   - Обложки открываются сразу (не "через раз", без долгой загрузки страницы).
   - Учебник с длинным названием не ломает выравнивание сетки на `/textbooks`.
   - Запустить проверку работы по предмету, учебник для которого загрузил
     ДРУГОЙ учитель (не тот, что делает проверку) — RAG должен подхватить его,
     без ошибки "учебник ещё обрабатывается"/"учебник не найден".

## Если что-то пошло не так

- Откат кода — обычный `git revert`/деплой предыдущего коммита. `pdf-lib`
  тогда нужно будет вернуть (`npm install` подтянет по восстановленному
  `package.json`), а PNG-обложки, сгенерированные новым кодом, старый роут
  (ищущий `.pdf`) просто не найдёт — значит после отката тоже нужно будет
  либо переиндексировать, либо повторно сгенерировать `.pdf`-обложки (обратной
  миграции нет, писать по необходимости).
- Если `@napi-rs/canvas` не грузится на проде (шаг 3) — обложки просто не
  будут генерироваться (это по дизайну некритичная функция, `tryRenderCoverPng`
  ловит исключение и логирует warning, весь остальной пайплайн индексации
  продолжает работать), но тогда стоит завести отдельную задачу на починку
  платформенной совместимости, не блокируя этот деплой из-за одних обложек.
