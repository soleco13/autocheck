# Деплой фикса: quiz-механика с несколькими вопросами под одним компонентом

**Коммит:** `3be5669` в `origin/master` (репозиторий `soleco13/autocheck`)
**Файл:** `backend/src/services/answer-parser.ts`

## Что чинит

Контрольный лист может содержать один компонент "Quiz" (`comp.id`), который
рендерит НЕСКОЛЬКО независимых вопросов (каждый со своей группой вариантов
`quiz_question` → `quiz_question_text` + `quiz_variants`). Старый парсер брал
`Object.values(shuffledVariants)[0]` — только первую группу вариантов, из-за
чего остальные подвопросы и их варианты ответа пропадали из отчёта, а тексты
вопросов при этом ошибочно склеивались в один. Подтверждено на реальной
сессии ученика: 6 слайдов по 2 вопроса каждый → раньше 6 задач с неполными
данными, после фикса 12 задач, каждая со своим текстом/вариантами/оценкой.

## Шаги на проде

1. Забрать коммит (без force, обычный fast-forward):
   ```bash
   cd /path/to/autocheck   # рабочая копия на проде
   git fetch origin
   git log --oneline HEAD..origin/master   # ожидается: 3be5669 fix: parse all question groups...
   git merge --ff-only origin/master
   ```
   Если на проде есть незакоммиченные/неспушенные изменения — сначала
   разобраться с ними (git status), не затирать.

2. Пересобрать backend (меняется только `.ts`, значит нужна пересборка):
   ```bash
   cd backend
   npm run build
   ```

3. Перезапустить ТОЛЬКО backend-процессы (фронтенд не затронут):
   ```bash
   pm2 reload autocheck-api
   pm2 reload autocheck-worker
   pm2 logs autocheck-worker --lines 50   # убедиться, что стартовало без ошибок
   ```

4. Проверить, что фикс применился — сделать тестовый recheck любой работы,
   где в контрольном листе есть слайд с двумя вопросами "Выбери один верный
   ответ" под одним заданием, и убедиться, что в отчёте оба вопроса видны
   как отдельные задачи со своими вариантами.

## Важно — существующие отчёты не пересчитываются автоматически

Фикс влияет только на НОВЫЕ проверки. Отчёты, которые уже были сгенерированы
ДО деплоя по материалам с такой bundled-quiz механикой, останутся неполными
(с одной задачей вместо двух на слайд) — их нужно перепроверить вручную через
кнопку "Проверить заново" в интерфейсе (или через `POST /api/checks` с тем же
`studentId`/`platformMaterialId`). Массовый пересчёт всех старых отчётов не
делается автоматически — это отдельное решение (стоит токенов ИИ на каждую
переоценку), решать по необходимости.

## Обратная совместимость (важно для DB)

Для обычных (не bundled) quiz-компонентов `platform_component_id` не
поменялся — значит `ON CONFLICT (control_sheet_id, platform_component_id)`
в таблице `tasks` продолжит апдейтить существующие строки, а не плодить
дубли. Для bundled-quiz (несколько вопросов в одном компоненте)
`platform_component_id` теперь имеет суффикс `_{groupId}` на каждый
подвопрос — для НИХ при первом recheck после деплоя в таблице `tasks`
появятся НОВЫЕ строки (старая объединённая задача останется как "осиротевшая"
запись, если её не почистить). Это ожидаемо и не требует ручного
вмешательства — просто у таких материалов после recheck строк в `tasks`
станет больше, чем было.
